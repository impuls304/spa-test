# ИИ-помощник по складскому учёту

Учебная реализация тестового задания для AI / Data Science разработчика.

## Текущий этап

Завершены часть 1 — нормализация записей движения товара — и часть 2 —
детерминированный прогноз потребности и расчёт рекомендуемой закупки.

## Архитектура

- `src/inventory_ai/normalization.py` — извлечение полей складской записи и
  итоговая функция `normalize_movement`.
- `src/inventory_ai/catalog.py` — загрузка и кэширование справочника,
  морфологическая нормализация названий и индекс поиска SKU.
- `src/inventory_ai/locations.py` — загрузка внешнего реестра объектов и индекс
  вариантов названий локаций.
- `src/inventory_ai/forecasting.py` — расчёт среднего расхода, страхового
  запаса, точки заказа, даты исчерпания и итоговой рекомендации закупки.
- `tests/` — модульные и сквозные тесты нормализации, справочников и прогноза.
- `dataset.json`, `catalog.json` и `locations.json` — тестовые данные и
  справочники товаров и объектов.

Явный SKU имеет приоритет: он приводится к стандартному виду и проверяется по
справочнику. Если кода в записи нет, товар ищется по леммам названия. При
неоднозначности функция возвращает `None`, а не выбирает товар случайно.

Лемматизация через `pymorphy3` и кэшируемый обратный индекс выбраны с учётом
масштабирования: названия загружаются из актуального справочника автоматически,
поэтому добавление тысяч товарных позиций не требует дописывать в код отдельные
условия и падежные варианты для каждого товара.

Прогноз строится функцией `forecast_demand` без языковой модели. Она использует
средний расход за последние четыре недели, переводит его в дневной расход и
учитывает остаток, поставку в пути, страховой запас, срок поставки, размер
упаковки и минимальную партию из каталога. Через `params` можно изменить окно,
параметры поставщика или рассчитать сценарий изменения спроса, не меняя код.
